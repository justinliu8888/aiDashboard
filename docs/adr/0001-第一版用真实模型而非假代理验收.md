# 第一版用真实模型验收，而不是 Fake Agent

## 状态

accepted

## 背景

项目里同时存在两条链路：一条走真实大模型（AgentScope + ReAct），一条是 `fake_report_agent.py` 提供的预置回复。Fake Agent 速度快、结果稳定，适合写确定性单测。

## 决策

第一版闭环的验收必须由**真实模型**跑通自然语言生成与编辑，不能只靠 Fake Agent 或预置回复就宣布闭环完成。Fake Agent 只用于状态流转等确定性单测。

同时，第一版的报表数值继续使用已生成好的模拟业务数据，不接真实业务取数——"模型是真的，数据是模拟的"这两件事不冲突。

## 原因

产品价值在模型的理解与规划能力上。用假代理验收，等于验证了 mock 自己，不构成对产品价值的证据。

但模型有波动，不适合承担所有断言。因此划分：确定性行为交给 `pytest` 断言，模型行为单独用真实模型跑，只检查关键条件是否满足。

## 后果

- 第一版验收会受模型输出质量与速度影响，测试需要允许一定波动，不能全部做成严格断言。
- 模拟数据与真实模型并存，沟通时必须说清是哪一层，否则容易出现"数据已接通"的误解。
