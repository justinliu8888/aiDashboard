# ADR 0005：对话式排版、草稿工作区与共享主题

日期：2026-11-02。状态：已接受（第 02 阶段实施期）。
关联：ADR 0003（下线网格拖拽布局编辑）、ADR 0004（模板态一律用模拟业务数据渲染）、
契约 `0002-draft-workspace-and-presentation.md`（本批冻结的 Interface）。

---

## 背景

第一批需求（页面 / 分组 / 组件 / 排版 / 外观 / 编辑闭环，33 项）要求：
用**对话**完成排版与外观修改，一次接受是**一个修改单位**，可以逐步撤销；
草稿要能打开、能另存为、能刷新恢复；主题要能在多份报表之间共享。

仓库当时的状态（实施期实测）：

- 报表定义是**扁平**的 `regions: list[dict]`，没有容器 / 分组 / 隐藏的概念；
- 造数与载荷**只遍历顶层 regions**，载荷按 `regionId` 关联定义里的 `id`；
- 种子串里含 `regionId`，所以展示 id 变了数值就会变；
- 编辑引擎只支持「改标题 / 改指标 / 换展示形式 / 改粒度 / 删指标 / 删卡片」这一类；
- 会话快照落 SQLite，但**没有**已应用修改的历史，没有撤销 / 重做，没有独立的草稿对象；
- 主题只有一个 `{"themeRef": "theme_default"}` 引用，没有注册表、没有解析、没有联动；
- 前端面板 `renderReportPanel()` 按**载荷顺序**平铺卡片，没有任何分组或排版能力。

---

## 决策

### 1. 排版与分组是**定义的一部分**，不是前端自己的树

容器区域用 `component.type == "CONTAINER"` + `children` 表达，**嵌在定义树里**。

- 不另造第二棵「前端专用树」：渲染消费的是权威定义。
- 载荷仍是**扁平的叶子列表**，按 `regionId` 关联；**容器不进载荷**（它没有数据）。
- 阅读顺序与排版由**定义树**决定，载荷顺序不再覆盖定义。

**为什么不用「容器引用子区域 id」**：移动 / 复制时会出现悬挂引用与半份状态；
嵌套字典让「移动 = 搬一个字典」保持原子性，与「整批失败不留下半份定义」一致。

### 2. 造数只吃**摊平后的叶子**，不让容器树进造数器

造数器与载荷组装只认「顶层区域列表」这一种形状。把容器树原样传进去会让
**组内子卡整批丢失**（造数器只遍历顶层）。

因此 `preview_service` 在给造数器的那**一份副本**上先递归取叶子、逐个适配
`previewSpec`，再摊平。原始定义（带容器树）不受影响。

### 3. 展示 id 与**数据身份**分开：`simulationIdentity`

- `previewSpec.simulationIdentity` = 数据身份；老卡片缺这个字段时**回退成它原来的
  `regionId`**（数值与改造前逐字节一致）。
- 种子用**数据身份**，载荷关联用**展示 id**。
- 移动 / 成组 / 改样式 → 身份不变 → 数值不漂。
- 复制 → 展示 id 换新的、身份沿用源的 → 复制件与源件数值一致，
  且复制件用 `duplicateOfRegionId` 标记，不参与总计。

### 4. 一次接受 = 一个修改单位；撤销恢复**内容**，版本**单调递增**

- 草稿对象（`draftId`）是**数据库对象身份**，独立于 sessionId / conversationId / messageId；
  同一草稿跨会话共享身份与锁。
- `metadata.revision` 是当前编辑版本，`savedRevision` 是显式保存版 —— 两者不同义。
- 撤销把历史游标前移并恢复内容，但**写入版本继续单调递增**：不回退乐观锁数值，
  否则「撤销后旧版本的请求会重新生效」。
- 新修改提交清掉旧 redo 分支；重开恢复同一游标与菜单，**不自动续跑**。

### 5. 草稿工作区是**数据库对象**，不是内存 store

`definition_save_service` 的内存版字典**不能**当生产保存 Adapter：进程一重启就丢。
本批新增 `draft_objects` / `draft_versions` / `draft_history` / `draft_tasks` / `draft_themes`
五张表（`CREATE TABLE IF NOT EXISTS` + 幂等补列），编辑记录与显式保存版**分开记**。

「编辑记录」与「显式保存」不是同一个动作：接受一次修改就产生可恢复的编辑状态，
显式保存才形成保存版，**都不自动发布**。

### 6. 主题是**共享数据库对象**，服务端解析

- 主题只有 `themeId` / `themeRevision` / 白名单 `tokens` / `defaultStyle`；
- 报表保存**主题引用**，渲染时由服务端 `resolve_theme` 解析成 `resolvedTheme` 下发；
- 应用主题会**清除主题管理的旧局部覆盖**（让主题重新生效），之后仍允许新的局部覆盖；
- 应用主题**不改**布局、统计口径与 FormatSpec；
- 模板保存前先给**影响摘要**并确认，再原子版本提交；使用该主题的报表**联动更新**。

### 7. 保持 ADR 0003：**无拖拽、无中间页**

本批**不**恢复网格拖拽，**不**新建模板 / 预览中间页。
所有排版与外观修改走对话；按钮只用于显示隐藏、打开 / 保存、撤销 / 重做这些已确认入口。
**新 ADR 不是重开旧网格** —— 拖拽那条线仍然关闭。

### 8. 显示隐藏开关**不写报表定义**

「显示隐藏内容」是**视图状态**：开启时按原阅读顺序插回半透明卡片并临时让位，
关闭时完全隐藏且其它内容补位。开关本身不解除隐藏、不改定义。

## 被否决的备选

| 备选 | 否决理由 |
| --- | --- |
| 前端自己维护一棵排版树 | 会与权威定义对不上；刷新 / 另存为 / 撤销后必然漂 |
| 容器引用子区域 id（`children: ["region_1"]`） | 移动 / 复制时出现悬挂引用，原子性难保证 |
| 种子继续用 `regionId` | 复制件数值必然与源件不同 —— 与「复制保留数据与统计口径」冲突 |
| 撤销时把 `metadata.revision` 一起退回去 | 旧版本的请求会重新生效，乐观锁失效 |
| 把「编辑记录」和「显式保存版」合成一个 | 用户分不清「已保存」与「已记录」，且撤销会误伤保存版 |
| 用内存字典当草稿保存 | 进程重启即丢；不满足「打开草稿」「另存为」 |
| 主题做成前端常量 | 其他报表打开 / 刷新会停在旧缓存；无法联动更新 |
| 恢复网格拖拽 | ADR 0003 已决定下线，本批不重开 |

## 后果

**正面**

- 排版、样式、主题都落在权威定义上，刷新 / 另存为 / 撤销后不会漂。
- 组内子卡与顶层卡片走同一条造数与渲染链路，不会「组里的卡没数」。
- 复制件的数值与源件一致，且不会让总计翻倍。
- 撤销是**内容**级别的，不是重新执行上一步；不会复活旧卡片目标。

**负面 / 代价**

- 定义从「只有扁平列表」变成「可以是树」：造数、载荷、校验、前端查找都要能递归。
  旧平面定义**零改动兼容**，但新代码路径多了一层。
- `session_service` 多了一个快照键（`draftId`），草稿对象与会话之间是一对多关系。
- 主题持久化在本批第一轮是**内存版**（存储 Adapter 由草稿工作区提供），进程重启后
  自定义主题会丢 —— 这条已登记为未完成项。

**历史兼容**

- 老定义（无 `children`）按只读默认渲染，**不为展示批量重写历史**；
- 老卡片的有效数据身份 = 它原来的 `regionId`，数值与改造前一致；
- 老会话没有 `draftId` 时，第一次拿到定义就建立基线（不产生撤销条目）。
