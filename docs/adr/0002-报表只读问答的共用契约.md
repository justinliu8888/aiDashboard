# ADR 0002：报表只读问答的共用契约

日期：2026-10-28。状态：已实施（Agent A），待协调者转发 B / C / D 确认后固定。
关联规格：[#12 报表只读问答](https://github.com/justinliu8888/aiDashboard/issues/12)。
实现分支：`feature/agent-a-readonly`（基线 `ccbe830`）。

本 ADR 冻结**共用后端编排**的契约：可信事实来源、事实状态口径、只读回答语义、
查询模式的工具权限、待确认入口和落库边界。C / D 的领域模块、前端展示都挂在这套契约上。

## 1. 可信当前会话上下文

新增 `app/services/session_fact_service.py`：

```python
session_fact_service.load(
    *,
    session_id: str | None,
    project_id: str = "",
    subject_ref: str = "",
    subject_id: str = "",
    request_has_draft: bool = False,
) -> SessionFacts
```

- **唯一事实源**是服务端会话记录（`session_service.repository.get_session`）。
  请求快照（`request.snapshots`）只作界面上下文与对象定位，**不作事实依据**。
- `request_has_draft` 只用来区分「新建对话（确实没有草稿）」和
  「页面有草稿但服务端记录查不到（不可确认）」，不用于判断草稿是否存在。
- 授权范围不一致时返回 `FORBIDDEN`：会话记录的 `snapshot.scope` 与本轮请求范围
  不符，或请求的业务对象不在授权范围内，都不能把里面的草稿说出去。

`SessionFacts`（`app/schemas/fact.py`）提供：`status`、`sessionExists`、`scope`、
`businessStage`、`draft`、`pendingEditPlan`、`pendingChoice`、`savedDefinition`、
`preview`、`clarificationRounds`、`reason`，以及只给服务端用的 `definition` / `policy`。

## 2. 事实结果的四种状态

`app.schemas.fact.FactStatus`：

| 状态 | 含义 | 回答口径 |
| --- | --- | --- |
| `FOUND` | 事实已核实 | 据实回答 |
| `ABSENT` | 确认没有该对象 | 明确说「当前对话没有」 |
| `UNAVAILABLE` | 读取失败 / 服务端记录不可得 | 说「暂时无法确认」，**不能**说成没有 |
| `FORBIDDEN` | 请求范围或权限不符 | 只说公开限制，不泄露内容 |

`SessionFacts.status` 描述会话事实整体的读取状态；
`SessionFacts.draft.status` 描述草稿这一项 —— 「会话读到了但里面没有草稿」
是草稿 `ABSENT`，不是会话读不到。

## 3. 事实工具

| tool | 类别 | 说明 |
| --- | --- | --- |
| `get_current_draft` | FACT（已升级） | 当前对话草稿概览。返回 `status`、`exists`、`reportName`、`revision`、`regions`、`pendingSteps`、`savedDefinition`、`preview`、`source`、`reason`。事实来自服务端会话记录。 |
| `get_current_session_status` | FACT（新增） | 已记录业务阶段、待确认修改计划、待确认选项、已保存定义、预览、澄清轮次。 |
| C / D 的事实工具 | FACT（各自新增） | 见 §7 接入方式。 |

## 4. 只读回答契约

### 4.1 提交工具

新增终结工具 `submit_query_answer`：

- `CONCLUSION_STATES = (SAME_STATE_CONCLUSION,)` ——「原地回答」：状态保持不变。
  `app/tools/base.py` 新增 `SAME_STATE_CONCLUSION = "SAME"`，表示结论状态 =
  调用时的当前节点（同一节点内继续推进本来就是合法转移）。
- 只在查询模式注册（模块级 `IS_QUERY_ONLY = True`）：普通业务轮的 Toolkit 里
  没有这个出口。
- 载荷 `QueryAnswerPayload`：`reply`（必填）、`facts[]`、`limitations[]`、
  `suggestions[]`、`needsClarification`、`clarificationQuestion`。

### 4.2 响应语义

`AgentResponse.turnKind`：

| 值 | 含义 |
| --- | --- |
| `action`（默认） | 正常业务轮，可能推进状态机 |
| `query_answer` | 只读查询回答轮，**本轮不推进业务** |

`query_answer` 轮的服务端强制不变量（`AgentService._normalize_query_answer`）：

- `state` == 本轮进入时的 state；
- `domainObjects.reportDefinitionDraft` / `reportPolicyDraft` 取服务端可信对象，
  服务端没有时才回退请求快照（仅用于展示）；
- `questions` = 原有待确认菜单；没有菜单时为空（不出现无关生成选项）；
- `uiActions == ["query_answer"]`；`toolRequests == []`；
- **问进度时**，`reply` 必须同时说清两件事：这是**已记录**的状态、
  **不是实时进度**（`app.schemas.fact.RECORDED_STAGE_DISCLOSURE`）。
  口径由共用层给定，服务端在模型漏说时补上 —— 不能只靠模型自觉：
  模型可能把这条边界写进 `limitations`（结构化字段，页面不渲染），
  也可能干脆没写。
  - 判定「已经说清」要求**两半都在**：一边是「已记录」类说法，
    另一边是「不是实时」类说法；缺一半就算没说清
    （「你的需求已记录」「没有实时任务状态来源」都不够）。
  - 答案里**编了实时进度**（百分比 / 正在跑）时，不能靠再补一句否认来
    抵消 —— 两句话会打架，用户读到的是假数字；服务端用会话事实
    换掉整句回答。
  - 只对**问进度**生效；问草稿、问能力不补这条边界。

### 4.3 前端如何识别「本轮不推进」

**`response.turnKind === "query_answer"`**。

不能只看 `state`：查询回答可能保留 `SAVE_DEFINITION_DRAFT` / `VALIDATING` 这类
会自动 `__advance__` 的状态，前端必须按 `turnKind` 决定不再调度推进指令。

答案文本在 `reply` 里，按普通文本气泡展示；原菜单在 `questions` 里单独渲染，
两者分开展示，答案不标成「需要你补充信息」。

## 5. 查询模式与工具权限

- 判定入口：`RouteDecision.userIntent == ASK_QUESTION`。
  路由器手里没有草稿 / 进度 / 能力事实，所以**不允许**它提前给结论：
  Concierge 的 `DIRECT_REPLY` 遇到 `ASK_QUESTION` 会被降级成深路由。
- 查询模式的 Toolkit 只注册：**全部 FACT 工具 + `submit_query_answer`**。
  组装草稿、保存、校验、预览、应用修改、接受 / 取消计划都不注册 —— 模型调不到。
  权限边界是结构性的，不只靠 Prompt 声称「请不要修改」。
- 降级路径（模型不可用）用 `routing_rules.is_readonly_question(message)` 兜底：
  疑问标记 + 报表业务对象 + 无明确改动动词，三条同时满足才算只读提问。

## 6. 待确认入口与落库边界

### 6.1 待确认入口

- 选项值 → 走原来的确认流程，一行不改。
- 其它自由输入 → 先路由：
  - `ASK_QUESTION` → 查询模式；
  - `UNKNOWN` 且是明确的只读提问 → 查询模式；
  - 其它 → 仍然按「必须从菜单里选」拒绝（`uiActions == ["selection_required"]`）。
- 查询模式下**不触发**任何执行动作（接受修改 / 确认报表 / 保存 / 校验 / 预览 /
  生成草稿）：`__advance__`、模板编辑、模板预览流在待确认期间一律跳过。
- 查询回答后：原菜单、pendingChoice、待确认修改计划、澄清轮次全部不变。

### 6.2 落库边界

`session_service.record_turn` 对 `turnKind == "query_answer"` 单独处理
（`SessionService._commit_query_turn`）：

- 允许追加 user / assistant 聊天消息；
- **不重建业务对象**：snapshot 沿用库里那份，不从请求快照重建；
- `state`、`designSessionId`、`reportDefinitionId`、`previewRunId` 沿用库中原值；
- 不写澄清计数、不动待确认计划。

另外补了一条既有的保护：本轮没带回草稿时（待确认期间的一次拒绝回复就会这样），
snapshot 里的草稿 / 已保存定义 / 预览沿用库里那份，不会因为一次交互就丢掉。

## 7. C / D 的接入方式

C / D 各自新增一个 FACT 工具和一个领域服务，**不改共用协议**：

```python
# app/tools/<your_tool>.py
NAME = "<tool_name>"
DESCRIPTION = "..."
PARAMETERS = {"type": "object", "properties": {}}
CATEGORY = ToolCategory.FACT
IS_READ_ONLY = True
APPLICABLE_STATES = ()          # 或 LOOKUP_STATES


def run(**kwargs) -> dict:
    ...
```

接入只需要在 `app/tools/registry.py` 的 `_TOOLS` 列表里加一行 —— 查询模式的
Toolkit 会自动包含新注册的 FACT 工具。

返回体约定：

- `status` 用 `app.schemas.fact.FactStatus` 的取值（`FOUND` / `ABSENT` /
  `UNAVAILABLE` / `FORBIDDEN`）；
- 可选 `summary`：面向用户的一句话，会被并进确定性回答（Fake 路径）与
  已核实事实列表；
- 进度类事实从 `session_fact_service.load(...)` 取 `businessStage` 等服务端事实，
  不从客户端快照取，也不自己另建一份状态枚举。

C / D 的工具**不需要**新增终结工具：答案统一由 `submit_query_answer` 提交。

### 7.1 领域模块状态词表与共用事实状态的映射

各领域模块在自己的契约里保留更细的词表（进度用「已记录阶段」，能力用
「目录登记 / 链路支持」），但**对共用层暴露的状态**必须落回四态，
否则「读不到」和「确实没有」会被混为一谈。

`app.schemas/fact.py` 提供 `to_fact_status(domain_status)` 做这件事，
映射表见 `DOMAIN_STATUS_TO_FACT_STATUS`：

| 模块 | 自有词表 | → 共用事实状态 |
| --- | --- | --- |
| 进度（`availability`） | `SUCCESS` | `FOUND` |
| | `NO_OBJECT` | `ABSENT` |
| | `UNAVAILABLE` | `UNAVAILABLE` |
| | `PERMISSION_DENIED` | `FORBIDDEN` |
| 能力（`outcome`） | `OK` | `FOUND` |
| | `REGISTERED_NOT_SUPPORTED` | `FOUND`（限制在 `execution.*.reason` / `mustState` 披露） |
| | `NOT_REGISTERED` | `ABSENT` |
| | `NOT_AUTHORIZED` | `FORBIDDEN` |
| | `MISSING_CONTEXT` | `FOUND` + 提交答案时 `needsClarification=true` |

工具返回体建议同时给出两样：自己领域里的细粒度字段，和折算出来的共用 `status`。

### 7.2 工具级标记 vs 响应级标记

- **响应级**：`AgentResponse.turnKind == "query_answer"` —— 这是前端判断
  「本轮不推进业务」的**唯一依据**。
- **工具级**：`answerKind` / `contractVersion` 之类是给模型看的领域标记，
  **不作为前端的判断依据**（模型看到的是工具 Observation，响应里没有它）。

### 7.3 注册改动（C / D 落地后由 A 补，共 4 行）

`backend/app/tools/registry.py`：

```python
from app.tools import (
    ...,
    get_recorded_progress_tool,     # C：查已记录进度
    check_product_capability_tool,  # D：查当前产品实际支持的能力
    ...,
)

_TOOLS: list[Any] = [
    # 只读事实
    ...,
    get_recorded_progress_tool,
    check_product_capability_tool,
    ...,
]
```

共用层不反向依赖领域模块：口径放在 `app.schemas/fact.py`（共用事实词汇），
领域模块与共用层引用同一句，避免两处各说各话。

工具名已固定：C 用 `get_recorded_progress`，D 用 `check_product_capability`
（与既有 `check_capability` / `search_catalog` / `get_current_draft` 的命名风格一致）。
注册后自动在全部业务节点可用，并自动继承注册层的三条保护：
异常 → `{"error": ...}`；`lookup_failure` 置位；`is_read_only` 语义不被终结工具污染。

## 8. 明确的边界

- 首版不回答「正在跑的请求实时到哪一步」：已记录阶段 ≠ 实时任务状态，
  不编百分比和剩余时间。
- 查询范围限当前对话，不检索历史会话；问历史草稿时引导到会话历史列表。
- 不把产品助手扩成万能聊天助手：只读提问判定要求指向报表业务对象。
- 本次不新增并发查询、实时监控、生产取数、布局能力。
