# ADR 0004：模板态一律用模拟业务数据渲染，取消独立预览阶段

日期：2026-10-29。状态：已决定。
依据文档：《需求稿 - 模板态全假数字与文字方案左移》（2026-10-29 反馈目录，
`反馈from zhiheng/20261029 改那个数据展示方式然后把文字放到右边对话框里/`）。
关联：ADR 0003（下线网格拖拽布局编辑）、ADR 0001（第一版用真实模型而非假代理验收）。

本 ADR 记录一项产品决策：**报表在"用户还没接入真实数据"的阶段，一律用系统生成的模拟业务数据
把它渲染出来，而不是画空壳**；并因此取消独立的报表预览面板。
本文只记录决策与取舍，不宣称实现状态；实际实施与交付时间以交付记录为准。

补充确认：用户明确批准合并原来的草稿展示与填数预览。系统在模板生成阶段就自动生成模拟数据并渲染，
因此取消独立预览面板不是额外范围扩张；后台校验与试运行仍保留。

---

## 1. 为何决定

### 1.1 用户口径

用户对当前形态的判断是明确的：

- 现在"有数才展示"，没数就画空壳（指标卡写死 `—`、表格 3 行 `—`、图表永远空壳、
  未接通指标显示"暂无数值 + 原因"）。用户要改成**无论如何都展示**。
- **后台不维护数据库**，由系统直接造假数字，并且按最贴合该板块形态的方式展示。
- 理由是产品形态本身：这是**模版**。用户存好模版，后面才会连上真的数字。

### 1.2 为什么"空壳"在模版阶段是错的

在一个还没有接入真实数据的阶段，用户要核对的是**版式**——板块对不对、图表形态对不对、
数字该出现在哪个位置。空壳只回答了"缺什么"，没有回答"长什么样"。
本项目的既有决策恰好是为**别的目标**服务的：

- ADR 0003 §4.4 写的是"确认前不取数，占位不编造数值"；
- 20261029 规格 User Story 3 是"显示为空壳加原因说明，以便我知道那里缺什么，**而不是被假数字骗过去**"；
- 20261029 规格 Problem Statement 第 7 行写的原问题是"确认方案之后，页面直接把一屏模拟数值摆出来，
  用户分不清哪些是真数据、哪些是还没取的占位"。

这三条针对的是**同一个风险：用户把占位当成结果**。用户本次的判断是：在模版阶段，
风险不是"占位太丑"，而是"看不到成品长什么样"。因此真正的解法不是回到空壳，
而是**把模拟数显式标成模拟数**——让用户既看到成品形状，又不会误读。

### 1.3 数据侧本来就没有真实取数

核对代码事实：预览链路取的是 `backend/app/services/mock_data_service.py` 的确定性伪随机
（MD5 种子），**不查询任何数据库**。数据库里存的是会话、消息、方案、模板、草稿定义，
**没有任何业务数值表**；`report_design_definitions.definition_json` 只存结构，
后端测试 `test_report_template_generation.py:440-442` 专门断言 region data 不含
`value / yValues / xLabels / rows / points`。

所以"不查数据库、全用假数字"在实现上等价于**不引入任何真实取数通道**——现状已经如此。
这一范围不等于删除数据库：现有会话、消息、方案、模板与草稿定义的持久化仍保留，历史用户数据不清理。
本次决定的实际内容是：**把模拟数据源从"试运行之后才用"提前到"草稿阶段就用"**，
并把它扩成能覆盖全部板块形态。

补充存储事实：没有业务数值表，不等于所有模拟结果都未落库。现有会话写入会保存完整响应，快照也会缓存预览载荷；
本轮实施须阻止新模拟结果经这些路径间接保存，并在读取响应时按定义与固定时间元数据重新生成。
这是待实施的存储边界，不宣称现有代码已满足；已有历史记录不清理、不迁移。

## 2. 决定内容

### 2.1 模拟业务数据成为模版阶段的默认数据来源

- 草稿确认后，右侧不再画空壳，而是用**模拟业务数据**把这份报表定义渲染成图与表。
- **所有**板块形态都出数：指标卡、图表、表格、数据质量，连系统**尚不支持**的指标
  （PUE、总电费、实时功率）也出数，但保留"能力待接通"的标注。
- 不引入真实取数通道；模拟数据由代码按固定种子确定性生成，**不入库、不落盘**。
- 同一份定义、同一时间窗，多次打开数字不变（刷新不跳数）。
- 首次确认固定定义版本的时间锚点，跨天打开及试运行复用；元数据可保存，模拟结果不保存。修改形成新版本时更新关联，防止旧载荷覆盖新模板。
- 模拟数严格按方案声明的时间范围与粒度生成。

### 2.2 报表定义仍然不含数值

草稿**在定义层面**保持纯定义：数值不进 `definition_json`，不随草稿落库。
屏上呈现的那份东西在术语上叫**「报表示意」**——定义 + 模拟业务数据的渲染，
用来核对版式；「报表预览」保留给将来接入真实数据之后。

跨板块一致性：相同对象范围与窗口的能耗系板块严格一致（卡片总量 = 表格各行之和 = 能量趋势各桶之和；功率趋势按时长积分；
总电费 = 总耗电 × 单价）。PUE、告警列表、机柜状态列表属于派生量与离散事件，
没有勾稽关系，只保证数值落在合理区间内。

### 2.3 表格的列由模型在方案里声明

模版的列结构必须现在就固定，否则将来接真实数据时列名对不上。
因此在文字方案里为表格板块声明列（`PlanSection` 增加仅表格使用的列定义），
模型在生成方案时一并给出，转换层落到 `component.columns`，模拟数据按列造行。

新方案缺列表示结构不完整，不表示没有真实数据。用户已确认：**系统优先提出合理栏目，判断不了才询问用户**。
可合理判断的栏目写入左侧文字方案供用户确认，不要求用户逐项设计表格，也不在渲染阶段偷偷补列。
确实无法判断且影响模板用途时，在左侧对话框提出具体问题；用户补充后完善方案，再确认并生成带数模板。
模型漏写已有明确依据的栏目由系统修正，不把技术错误转嫁为用户追问；修正失败时明确提示、允许重试，不能默默渲染空表。
旧方案优先复用已有列；确实缺列的历史方案兼容策略仍待确认，不自动改写历史数据。
“所有板块出数”以结构完整为前提，不掩盖结构错误；具体规则见需求稿第 4.1 节。

### 2.3.1 展示类型在生成方案时选择

系统根据模板请求中的指标、时间粒度、维度和展示目的，选择当前支持的展示类型，再生成匹配的模拟数据。
总量优先指标卡，时间变化优先趋势图，对象比较优先柱状图或排名图，记录明细优先表格；用户明确指定且支持的类型优先。
选择及简短理由呈现于文字方案。用户确认后按该类型渲染，不让随机生成的数值反过来改变已确认版式。
本轮不要求先上传真实数据，不新增图表库；验收以可读、单位清楚、布局不溢出和展示目的匹配为准。

### 2.4 取消独立的报表预览阶段

草稿阶段已经是带数的报表，点「同意」之后**右侧不再变一次**：

- 数字不动（同一套造数器、同一时间窗 → 草稿里看到的数与试运行出来的数完全一致）；
- 顶部徽标从"草稿"变为"已校验 / 待接真数"；
- 后台的校验与试运行**照跑**，代码保留在主线，将来接真实数据直接复用。
- 只有校验成功才显示“已校验”；进行中或失败时保持示意可见并显示实际状态。

含独立预览面板的完整版代码保留在分支 `feature/preview-stage-full`
（存档点 `pre-20261029-preview-stage`），需要时可取回。
必须先核对并保存旧版完整源码（含必要的未提交文件），再回 `main` 开发；只给旧 `HEAD` 建分支不算保存完整工作区。
不混入凭据、运行数据库或日志，不覆盖已有分支/标签，不丢弃用户改动；详细实施顺序以需求稿第 8 节为准。

### 2.5 标注强度：弱标注

- 面板顶部一行小字说明当前数值为模拟业务数据；
- 每块加角标；
- 系统尚不支持的指标，在角标之外额外写明"能力待接通"。

**不做**完全不标注（等于把 20261029 规格 Problem Statement 第 7 行的原始问题原样装回来），
**不做**满屏水印（挡演示）。

## 3. 为何不选其它做法

| 备选 | 为何不选 |
| --- | --- |
| 保持空壳，只在有数据时展示 | 与"模版要能看到成品形状"的目标直接冲突；用户本次明确要求反转。 |
| 草稿定义扩成"定义 + 示例数据"并落库 | 与"后台不维护数据库"冲突；且"用户同意的是一份带数的草稿"与"同意一份纯定义"语义不同。 |
| 让转换层按板块标题推导表格列 | "告警列表"要猜成告警级别/设备/时间，"机柜运行状态"要猜成套机柜/状态/负载率；猜出来的列接真实数据时必然对不上。 |
| 渲染时按模拟数字重新挑选组件类型 | 与已确认方案冲突；允许且要求在生成方案时按请求和数据特征选择类型，但不能在确认后静默改写。 |
| 不支持的指标不造数，继续占位 | 与"无论如何都展示"冲突；这类板块会继续是空壳，模版里最难看的一块留白。 |
| 完全不标注 | 把 20261029 规格记录的原始信任问题原样装回来。 |
| 取消校验与试运行 | 把"接真实数据"的那条路堵死，将来要把存档分支合回来，而主线已改不少，合并会冲突。 |
| 给未支持指标造假数却不标注 | 等于承诺一个系统交付不了的口径（PUE 至今没有已确认口径），撞开工单 05 的"不编造数值或 PUE 公式"。 |

## 4. 这个决定推翻了哪些既有约束

| 原约束 | 出处 | 处置 |
| --- | --- | --- |
| 确认前不取数、占位不编造数值 | ADR 0003 §4.4 | **本 ADR 取代**。草稿阶段不取真实数，但用模拟业务数据渲染。 |
| 确认方案后页面上没有任何业务数值 | 20261029 规格 US4 | **本 ADR 取代**。 |
| 未取到的区域显示空壳加原因、不被假数字骗过去 | 20261029 规格 US3 | **部分保留**——原因说明仍在，但不再以空壳呈现；改以"能力待接通"角标保留。 |
| 不编造数值或 PUE 公式 | 工单 05 | **本 ADR 取代**（就"是否呈现数值"而言）；PUE 仍不编造**公式**，只是呈现一个标注为模拟的数值。 |
| 草稿生成阶段停止提前取数 | 工单 04 | **保留其"不取真实数"的部分**，取代其"草稿不出数"的部分。 |

被取代的约束不删除，只在本 ADR 与术语表里改写口径；历史文档按 ADR 0003 §5 的做法加标注保留现场。

## 5. 实施边界（硬约束）

1. 模拟业务数据只存在于响应与内存，**不建业务数值表、不落盘**；保留现有会话、方案及纯定义存储，不删除数据库或历史用户数据。“纯定义”不含业务结果，但允许列宽、版本等数值配置。
2. 模拟数由代码按固定种子生成，**同一份定义 + 同一时间窗 → 数字恒定**。
3. 组件类型一律取自已确认方案，系统**不得**改写板块形态、不得静默套用默认类型。
4. 表格列必须来自方案声明，系统不得按标题猜测。
5. 系统尚不支持的指标：出数 + 保留"能力待接通"标注；**不编造计算口径或公式**。
6. 数值一律带弱标注；不得出现无标注的模拟数值。
7. 文字方案呈现于**左侧对话区**，右侧不出现文字方案。
8. 校验与试运行代码保留在主线，不得因为取消预览面板而删除。
9. 不引入真实业务取数通道；真实取数是后续独立决策。
10. 历史会话、历史方案、历史草稿不迁移、不改写；结构完整的旧会话按模拟数据渲染，但不自动取真实数、不隐式确认；缺列历史方案的兼容策略待确认。

## 6. 日后若要改回需要先满足什么

1. **先证明模拟数据够用**：给出具体场景，说明"模版阶段用模拟数"在哪一类真实需求上无法收敛。
2. **真实取数通道先落地**：要恢复"有数才展示"，必须先有真实取数能力并接通，
   否则用户看到的将只剩占位。
3. **标注机制要先解决**：若要去掉"能力待接通"标注，前提是系统能明确区分
   "这个指标系统算得出来"与"这个指标只是暂时没接"——目前两者在目录层面无法区分。
4. **重走一轮规格与工单**，并补一份说明取舍的新 ADR；不以"恢复旧分支"的方式复活被下线的预览面板。
