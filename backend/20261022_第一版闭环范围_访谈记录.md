## 一、已确认的范围

| 编号 | 决定 |
| --- | --- |
| Q1 | 第一版闭环到：用户提出报表需求、生成草稿、看到报表预览，并能确认或修改后再次预览。发布和导出暂不纳入。 |
| Q2 | 允许使用明确标注的模拟业务数据验收第一版闭环；接入真实业务取数不作为这一版的完成条件。这里的模拟数据不是模拟大模型。 |
| Q3 | 先保证一种典型报表能够完整走通。 |
| Q4 | 不接受“只做一次简单修改”的范围。组合修改、含糊指令的追问以及相关状态转换也属于第一版目标。 |
| Q5 | 编辑能力包括组合修改、含糊指令追问、只查询不修改、修改前确认。 |
| Q6 | 状态转换除成功路径外，还包括追问、取消修改、重新开始、确认、失败后重试、恢复会话后的状态。 |
| Q7 | 第一版选“A 机房能耗日报”作为必须跑通的典型报表。 |
| Q8 | 自然语言生成和编辑必须跑通真实大模型；不能只靠 Fake Agent 或预置回复来声明闭环完成。 |
| Q9 | 报表预览使用现有已生成好的模拟能耗数据；第一版不接真实业务取数，但生成和编辑仍必须由真实大模型完成。 |
| Q10 | 数据源目录、指标目录和权限判断可以沿用现有本地能力；不是本轮重点，但必须存在且在闭环里正常工作，不能因模拟数据而跳过权限校验。 |
| Q11 | “接受修改”只更新草稿；之后“确认报表”才保存并生成新预览。这是两个独立的用户动作。 |
| Q12 | 第一版的标准输入为“生成 A 机房昨日能耗日报”；产物是用户可见的标题、关键数值、趋势图和明细。 |
| Q13 | 模型运行期间不允许切换会话；模型跑完、等待用户输入时切走再恢复，必须回到原来的待处理状态，既不丢问题，也不擅自应用未接受的修改。 |
| Q14 | 模型执行失败或超时时，说明失败原因并允许重试；已有草稿保持原样不被破坏。 |
| Q15 | 用户点“停止”只中断 AI 思考；上一份已确认的草稿继续保留，不被半截结果覆盖。 |
| Q16 | 用户要求使用无权限的数据源时，明确说明授权范围不足并给出可行替代；不擅自换源，也不假装成功。 |
| Q17 | 过期计划必须被拦住：待确认计划绑定的草稿版本与当前草稿不一致时，不提供“接受修改”选项，提示重新说明；后端接受时同样校验版本，不一致则拒绝执行。 |
| Q18 | 同一项修改最多追问三轮；仍未明确就说明卡点并给出可选做法，不猜测着修改。 |
| Q19 | 纯提问（如“这个能按分钟看吗”）只作答，不弹修改菜单、不改草稿。 |

## 二、明确不纳入第一版

- 报表发布、导出 PDF/Excel。
- 接入真实业务取数与真实数据服务。
- 多用户、公开访问、项目归组与鉴权体系。

## 三、验收链路

四层各管一件事，不互相替代。确定性部分必须稳定通过；模型部分允许波动，只断言关键条件。

| 层 | 验什么 | 工具 | 判定标准 | 对应范围 |
| --- | --- | --- | --- | --- |
| L1 后端确定性 | 状态怎么转、草稿怎么变、接口返回什么、权限是否拦住 | `pytest`（`backend/tests/`） | 必须全通过，无随机失败 | Q1、Q6、Q10、Q11、Q14、Q15、Q16、Q17、Q18 |
| L2 前端页面 | 页面能不能打开、结构对不对、控制台有没有报错 | `frontend-self-check` | 必须全通过 | Q12 |
| L3 前端交互 | 点得动吗、锁得住吗、状态切换对吗、恢复会话对吗 | `frontend-interaction-check`（`flows/`） | 必须全通过 | Q11、Q13、Q15、Q17、Q19 |
| L4 模型行为 | 听不听得懂、问不问得准、摘要写得对不对 | Evalite（`evals/`），打真实后端 | 看关键条件命中率与失败样本，不要求逐字一致 | Q5、Q7、Q8、Q19 |

### L1 后端确定性

```bash
cd backend && pytest
```

- 用 Fake Agent 和假工具结果，断言状态落点、草稿 revision、changeSet 路径、拒绝原因。
- 覆盖：正常生成、追问、拦截、编辑接受/取消/调整、组合修改原子性、追问轮数上限、过期计划拒绝、会话持久化与恢复。
- 现有资产：`tests/test_state_transitions.py`、`test_template_editing.py`、`test_session_edit_state.py`、`test_session_store.py`、`test_session_stream.py`、`test_edit_resolvers.py`、`test_tools.py` 等。
- 集成前实际基线为 8 个旧契约失败（6 个“立刻应用”、2 个 snapshot 存储/锁假设）；已按候选计划确认流程迁移，并修复纯查询误出计划、组合请求漏改粒度等真实缺陷。最新确定性回归为 `277 passed`。

### L2 前端页面

```bash
node .trae/skills/frontend-self-check/scripts/selfcheck.mjs --config 20261012\ 智能报表功能/ai功能/checks.json
```

- 断言页面渲染出来、关键文案在、控制台无报错，并留存截图。
- 注意：`checks.json` 目前指向 v3 原型目录，实际要验的 `frontend/pages/workbench.html` 需要补一个配置项。

### L3 前端交互

```bash
node .trae/skills/frontend-interaction-check/scripts/interact.mjs --config 20261012\ 智能报表功能/ai功能/flows/<页面>.flow.json
```

- 模拟真人点击/输入/选择，逐步断言，每步自动捕获 JS 报错，失败保留截图。
- 现有资产：`flows/` 下 8 个流程文件，已覆盖待确认计划确认与过期拦截、会话下拉恢复、请求期间锁定会话、新建会话、预览编辑工具等。
- 逐个看截图确认视觉上也对，断言只能查结构。

### L4 模型行为

```bash
cd 20261012\ 智能报表功能/ai功能/evals && npm run eval:run
```

- 跑之前先起后端：`cd backend && uvicorn app.main:app --port 8000`。
- 打的是真实 HTTP 接口 `/api/agent/chat`，走真实模型。
- 现有 6 个用例：正常生成、信息不足、权限越界、能力不支持、改 7 天趋势、删趋势图。4 个 scorer：状态落点、拦截码、变更集命中目标、协议字段完整。
- 断言方式：不要求模型逐字输出相同，只断言状态落点、拦截码、changeSet 命中目标、协议字段完整这些可判定的条件。
- 失败样本要留存并复盘，不允许靠调低断言绕过。

## 四、跑起来的顺序

1. `pytest` 全绿（先分清 7 个失败的性质）。
2. 静态自检：页面能打开、无报错。
3. 交互冒烟：点击、选择、恢复都对。
4. Evalite 跑真实模型：看命中率与失败样本。
5. 人工走一遍完整闭环：生成 → 预览 → 修改 → 接受 → 确认 → 新预览。

## 五、术语约定

| 词 | 含义 | 别用 |
| --- | --- | --- |
| 报表草稿 | 用户描述需求后生成的报表定义，待确认，不代表已出数 | 报表、模板、方案 |
| 报表预览 | 已确认草稿渲染成的图和表，是数据快照 | 报表、结果、报告 |
| 接受修改 | 同意一项待确认改动，只改草稿，不保存、不触发预览 | 确认、保存、提交 |
| 确认报表 | 对整份草稿表示同意，据此保存并生成新预览 | 接受修改、发布 |
| 待确认修改计划 | 尚未被接受的一项或一组改动，绑定草稿版本 | 修改、指令、变更单 |
| 澄清追问 | 意图不足时给出的具体选项或问题 | 报错、降级文案 |
| 模拟业务数据 | 预设的能耗数值与数据目录，不代表生产取数 | 假数据、Mock 模型 |
| 真实模型 | 实际调用的大语言模型，负责理解意图、生成与修改草稿 | 大模型、LLM、Agent |
