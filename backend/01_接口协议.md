# 智能报表 AI 后端接口协议

> **部分取代标注（2026-10-29，ADR 0004）**
>
> 本协议整体仍然有效。ADR 0004（`docs/adr/0004-模板态一律用模拟业务数据渲染.md`）
> **部分取代**了其中与「模板态是否呈现数值」「独立预览面板」相关的条款。
> **正文一字未改**，以下只标注各条款的现状，历史现场保留不删。
>
> 本文不含「占位不编造数值」「草稿不出数」这类成句旧口径；与之最接近的是
> §12.3 的快照 `previewPayload` 落库与恢复优先级，以及 §3.3 缺少 `reportPreviewPayload`。
>
> **被 ADR 0004 部分取代的条款**
>
> - §3.3 `AgentResponse` 字段表：**新增**聊天响应顶层可空字段 `reportPreviewPayload`
>   （含 `previewContext` 与 `regions[]`），区域载荷与现有预览载荷**同构**。
>   字段名沿用 "preview" 字样，只是为了让草稿与预览复用同一套渲染逻辑；
>   术语上草稿阶段那份是**「报表示意」**，不是「报表预览」——
>   「报表预览」保留给将来接入真实数据之后。
>   **（2026-10-29 落地：§3.3 已补上该字段及其结构说明。）**
> - §12.3 `snapshot` 字段口径中「`previewPayload`｜预览运行的结果体；恢复时直接渲染，不再重跑」：
>   **部分取代**。模拟业务结果**不得**写入会话快照 `previewPayload`；
>   恢复会话时通过既有会话读取入口，在响应 `snapshot.reportPreviewPayload` 上
>   临时附加同构载荷（仅线上响应，不写回持久化快照）。
> - §12.3「恢复优先级：`previewPayload` 存在 → 直接渲染最终报表；否则有 `definition` → 渲染草稿预览」：
>   **部分取代**。恢复时按定义与固定时间上下文重新生成载荷，不依赖已消失的内存 runId；
>   其中「草稿预览」这一措辞在术语上应为**「报表示意」**。
> - §2.1 状态枚举与 §2.2 状态转移中「点『同意』后右侧按预览状态切换渲染入口」的行为：
>   **被取代**（ADR 0004 §2.4 取消独立预览面板）。**状态机本身不变**——
>   后台的校验与试运行照跑，代码保留在主线。
>
> **仍然有效、继续适用的条款**
>
> - §2.1 状态枚举（`PREVIEWING` / `PREVIEW_READY` / `RENDERING` / `READY`）与 §2.2 允许的状态转移；
> - §8.3 `CREATE_PREVIEW_RUN` / `QUERY_RUN_RESULT`，以及 §11 分工表中
>   「预览｜发出 `CREATE_PREVIEW_RUN` 请求、解释结果｜实际取数 / 计算 / 质量检查」；
> - §5.5 禁止事项「不得编造 `datasets[*].sourceRef`、`pipelines[*].nodes[*].metricRef`……」——
>   约束的是数据源与指标绑定，与"是否呈现数值"无关，仍然有效；
> - §1.4 字段命名风格、§1.5 对象边界、§5.2 首功能必须返回的顶层字段：
>   「报表定义不含任何数值」依然成立——模拟数值只在响应与内存中，不落库。
>
> 取代关系与理由见 ADR 0004 第 4 节；术语以 `GLOSSARY.md` 为准。

> 定位：把 `00_统筹.md` 第 4 章状态机、第 5 章接口草案落到可实现的字段粒度，服务首功能「自然语言生成机房耗电量报表草稿」。
>
> 协议所有 `ReportDefinition` 相关字段严格对齐 `原始文件/report-definition-v1.md`。本文件只负责「AI 后端对外的对话协议」，不重新定义 `ReportDefinition` 内部结构。

## 1. 通用约定

### 1.1 版本

| 字段 | 值 | 说明 |
| --- | --- | --- |
| `agentProtocolVersion` | `1.0` | 本接口协议版本；向下兼容走补字段，不删字段 |
| `reportDefinition.schemaVersion` | `1.0` | 必须等于 `report-definition-v1.md` 的协议版本 |

### 1.2 ID 命名

| 对象 | 前缀 | 示例 |
| --- | --- | --- |
| 对话 | `conv_` | `conv_001` |
| 会话（可持久化对话） | `sess_` | `sess_9f2c1a4b7e10` |
| 消息（幂等键） | `msg_` | `msg_1758216000123_a4f2` |
| 项目（历史项目分组） | `ws_` | `ws_3c1d9f04` |
| 设计会话 | `session_` | `session_001` |
| 报表策略 | `policy_` | `policy_001` |
| 报表定义 | `def_` | `def_001` |
| 预览运行 | `run_` | `run_001` |
| 区域 | `region_` | `region_total_energy` |
| 意图 | `intent_` | `intent_timewindow_01` |

区域 ID 必须稳定；移动区域、改排序、改层级都不能变更 ID（参考 `report-definition-v1.md` 第 3 节「id」与第 11 节「IntentBinding」）。

> **三个 id 不要混用**（会话管理系统引入，详见 `07_会话管理系统方案.md`）：
>
> | id | 谁生成 | 生命周期 | 用途 |
> | --- | --- | --- | --- |
> | `sessionId` | **后端**（`POST /api/sessions`） | 一条对话从建到删，永不改变 | 持久化主键、侧边栏列表、恢复入口 |
> | `conversationId` | 前端 | 一次请求线程；**用户点「停止」时会换新** | 后端日志追踪、隔离迟到响应 |
> | `messageId` | 前端 | 一条用户消息 | 幂等去重键 |
>
> 之所以要独立出 `sessionId`：前端停止生成时会换新 `conversationId`，若按 `conversationId` 建会话行，一次停止就会把一条对话劈成两条历史记录。

### 1.3 时间与时区

- 所有对外时间字段使用 ISO 8601，例如 `2026-10-15T08:00:00+08:00`。
- 窗口的业务时区在 `ReportDefinition` 的 `WindowOverride.value.timezone` 字段表达，不在本协议顶层重复。
- 运行逻辑时间统一由 Java 后端固定；AI 后端不自行取 `now()`。

### 1.4 字段命名风格

接口统一使用 **camelCase**；与 `report-definition-v1.md` 保持一致。不要混用 snake_case。

### 1.5 对象边界重申

| 对象 | 来源 | AI 后端对它的权限 |
| --- | --- | --- |
| `ReportPolicy` | `report-definition-v1.md` 第 1 节 | 可生成/修改草稿；不定周期调度、不设凭证 |
| `ReportDefinition` | 同上 | 可生成/修改草稿；不写库、不发布 |
| `ReportDesignSession` | 同上 | 读上下文；写入由 Java 后端做 |
| `ReportRun`（预览） | 同上 | 读取结果、解释质量；不发起正式执行 |
| `ReportRelease` | 同上 | 只读；首功能不生成发布 |

## 2. 状态枚举

### 2.1 `AgentState`

对应 `00_统筹.md` 第 4.2 节，12 个状态必须严格使用下列字符串：

| 值 | 含义 |
| --- | --- |
| `ANALYZING` | 收到用户输入，进入语义分析 |
| `NEEDS_CLARIFICATION` | 关键信息不足需追问 |
| `BLOCKED_OR_UNSUPPORTED` | 权限不允许、能力不支持或危险动作 |
| `DEFINITION_DRAFT_READY` | 已生成定义草稿或 `ChangeSet` |
| `WAITING_USER_CONFIRM` | 等待用户确认框架 |
| `SAVE_DEFINITION_DRAFT` | 用户已确认，待保存草稿 |
| `VALIDATING` | 草稿保存后，调 Java 校验中 |
| `VALIDATION_FAILED` | 校验失败，待修正 |
| `PREVIEWING` | 发起 `ReportRun` 预览 |
| `PREVIEW_READY` | 预览结果就绪 |
| `RENDERING` | 渲染报表预览 |
| `READY` | 完整预览完成，可继续修改 / 保存 / 发布前检查 |

### 2.2 允许的状态转移

| 当前状态 | 允许进入的状态 |
| --- | --- |
| `ANALYZING` | `DEFINITION_DRAFT_READY`、`NEEDS_CLARIFICATION`、`BLOCKED_OR_UNSUPPORTED` |
| `NEEDS_CLARIFICATION` | `ANALYZING` |
| `DEFINITION_DRAFT_READY` | `WAITING_USER_CONFIRM` |
| `WAITING_USER_CONFIRM` | `SAVE_DEFINITION_DRAFT`、`ANALYZING` |
| `SAVE_DEFINITION_DRAFT` | `VALIDATING` |
| `VALIDATING` | `PREVIEWING`、`VALIDATION_FAILED` |
| `VALIDATION_FAILED` | `ANALYZING` |
| `PREVIEWING` | `PREVIEW_READY` |
| `PREVIEW_READY` | `RENDERING` |
| `RENDERING` | `READY` |
| `READY` | `ANALYZING` |
| `BLOCKED_OR_UNSUPPORTED` | 终止（会话内不再推进；可开新会话） |

AI 后端必须按此表推进；返回不在允许集合内的 `state` 视为协议错误。

## 3. 对话入口接口

### 3.1 接口定义

```
POST /api/agent/chat
Content-Type: application/json
```

AI 后端对外**唯一**对话入口。不按按钮拆多个 AI 接口。

### 3.2 `AgentRequest`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `agentProtocolVersion` | string | 是 | 固定为 `1.0` |
| `conversationId` | string | 是 | 对话 ID，`conv_` 前缀；一次请求线程 |
| `resumeOfConversationId` | string / null | 否 | 指向被中断的那次请求，用于日志关联与重放去重 |
| `sessionId` | string / null | 否 | **会话 ID**，`sess_` 前缀；一条对话从建到删不变。不传则退回用 `conversationId` 作为存储键（老前端等价行为） |
| `messageId` | string / null | 否 | **本条用户消息的幂等键**；同一轮重发复用同一个 id，后端按 `(sessionId, messageId)` 去重 |
| `state` | `AgentState` | 是 | 当前状态，来自上一次响应或初始 `ANALYZING` |
| `message` | string | 是 | 用户本轮输入；可为空字符串但字段必传 |
| `context` | `AgentRequestContext` | 是 | 调用上下文 |
| `snapshots` | `AgentRequestSnapshots` | 否 | 可选的服务端已知对象快照摘要 |

> **落库规则**（会话管理系统，v1.1 起生效）：
>
> 1. `sessionId` 与 `messageId` 均为**可选新增**，不改变既有必填字段，老前端不传时行为等价。
> 2. 一轮对话落库为 **user + assistant 成对**写入，且仅在请求**成功后**落库；被中断的请求不留半截记录。
> 3. `message = "__advance__"` 是流程自动推进的内部控制消息，**不写 user 消息**，但保留 assistant 的进度回复（用户看得见）。
> 4. user 消息只存用户实际输入。
> 5. 消息按 `(sessionId, messageId)` **幂等 upsert**：已存在则覆盖，不新增重复行。
> 6. Debug Trace 不入库。

#### `AgentRequestContext`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `designSessionId` | string / null | 否 | 已有设计会话则必传；没有则由后端创建 |
| `reportPolicyId` | string / null | 否 | 关联策略；首次生成可为空 |
| `reportDefinitionId` | string / null | 否 | 关联定义；修改草稿时必传 |
| `baseDefinitionRevision` | integer / null | 条件必填 | 生成 `ChangeSet` 时必传，用于并发编辑校验（见 `report-definition-v1.md` 第 11 节） |
| `selectedRegionId` | string / null | 否 | 局部修改时优先传，避免靠数组下标定位 |
| `projectId` | string | 是 | 用户所在项目 |
| `subjectRef` | string | 是 | 业务对象类型，首功能为 `machine_room` |
| `subjectId` | string | 是 | 业务对象 ID，例如 `room_a` |

#### `AgentRequestSnapshots`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `reportPolicy` | `ReportPolicyDraft` / null | 否 | 服务端已知策略摘要；最终以 Java 保存版本为准 |
| `reportDefinition` | `ReportDefinitionDraft` / null | 否 | 服务端已知定义摘要 |
| `lastChangeSet` | `ChangeSet` / null | 否 | 上一次已应用变更 |
| `lastValidationResult` | `ValidationResult` / null | 否 | 上一次校验结果（见 §7） |
| `lastReportRun` | `ReportRunPreview` / null | 否 | 上一次预览结果摘要 |

### 3.3 `AgentResponse`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `agentProtocolVersion` | string | 是 | 固定为 `1.0` |
| `conversationId` | string | 是 | 回传请求中的 `conversationId` |
| `state` | `AgentState` | 是 | 下一状态；必须属于 §2.2 允许的转移 |
| `reply` | string | 是 | 给用户展示的解释、追问、确认或错误说明 |
| `designSessionId` | string / null | 否 | 新建或已有的设计会话 ID |
| `domainObjects` | `AgentResponseDomainObjects` | 是 | 结构化领域对象（可全为 null） |
| `questions` | List<`AgentQuestion`> | 否 | 追问问题；仅在 `NEEDS_CLARIFICATION` 返回非空 |
| `blocks` | List<`AgentBlock`> | 否 | 拦截原因；仅在 `BLOCKED_OR_UNSUPPORTED` 返回非空 |
| `toolRequests` | List<`ToolRequest`> | 否 | 需要 Java 后端或受控工具执行的动作 |
| `uiActions` | List<`UiAction`> | 否 | 前端下一步按钮或展示动作 |
| `error` | `AgentError` / null | 否 | 协议级错误（见 §8） |
| `reportPreviewPayload` | object / null | 否 | **报表示意**载荷：草稿阶段就带着模拟业务数据。结构见下 |

#### `reportPreviewPayload`

草稿阶段（方案确认后）响应顶层带的**报表示意**载荷：各区域已经用系统生成的
模拟业务数据填满，前端**不需要二次请求**就能渲染。

```
{
  "previewContext": { ...八个字段... },
  "regions": [ { "regionId", "name", "role", "componentType", "payload" } ]
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `previewContext` | object | 示意上下文，**只放上下文、不放业务数值**。八个字段：`definitionId`（方案 id）、`definitionVersion`（方案 revision，整数）、`timezone`、`anchorTime`、`windowStart`、`windowEnd`、`grainUnit`、`generatorVersion`。时间窗**左闭右开**。 |
| `regions[]` | List | 区域载荷，与现有公开预览载荷**逐字段同构**，前端复用同一套渲染逻辑。 |
| `regions[].role` | string | **必须带**（如 `REPORT_TITLE`）。前端据它跳过标题区；`role == "REPORT_TITLE"` 的区域不出数、不进 `regions`。 |
| `regions[].payload.unit` | string | 数值型组件（`METRIC_CARD` / `CHART`）的载荷**必须带单位**；无量纲就是空串，不写错的单位。表格列的单位在 `payload.columns[].format.unitLabel`。 |

规则：

- **不落库**：模拟业务数据只存在于响应与内存。会话快照走允许列表（`definition` /
  `policy` / `reportPlan` / `templateDesign` / `designPhase` / `previewContext`），
  **不含** `reportPreviewPayload`；既有 `previewPayload` 的语义不变，只装试运行结果。
- **恢复**：恢复会话时按定义与**冻结的**上下文重新生成（确定性种子保证同定义同窗口
  结果完全一致），在响应 `snapshot.reportPreviewPayload` 上**临时附加**，不写回持久化快照。
- **失败**：造数失败（定义非法 / 时间窗推不出来 / 粒度解析不了 / 表格没有列）时明确报错，
  **不退回空表、不给半份载荷**。
- **不是校验成功**：报表示意 ≠ 校验通过，也不设置试运行成功状态。

#### `AgentResponseDomainObjects`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `reportPolicyDraft` | `ReportPolicyDraft` / null | 否 | 首次生成或更新策略草稿时返回 |
| `reportDefinitionDraft` | `ReportDefinitionDraft` / null | 否 | 生成或修正报表定义草稿时返回 |
| `changeSet` | `ChangeSet` / null | 否 | 修改已有定义时返回 |
| `reportRunPreview` | `ReportRunPreview` / null | 否 | 预览完成后返回 |

> 规则：AI 返回的草稿必须完整自洽（可脱离上下文读取），但不替代 Java 的保存与校验；`revision`、`status`、`id`（由服务端分配的部分）仍以 Java 回写为准，参见 `report-definition-v1.md` 第 2 节 `ReportMetadata`。

## 4. `ReportPolicyDraft`

首功能只需策略最小子集，用于把「谁用、看哪个对象、允许哪些覆盖」固定下来。字段严格对齐 `report-definition-v1.md` 第 1 节 `ReportPolicy` 与第 2 节 `PolicyBinding`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string / null | 否 | 由 Java 后端分配；AI 生成时留空 |
| `name` | string | 是 | 策略业务名称，例如 `A 机房能耗日报` |
| `description` | string | 否 | 用途说明 |
| `subjectRef` | string | 是 | 对齐 `ReportDefaults.scope.subjectRef`，首功能为 `machine_room` |
| `allowedOverrides` | List<enum> | 是 | 允许的覆盖域；可选 `TIME_WINDOW`、`GRAIN`、`QUALITY`、`COMPUTATION`（见 `PolicyBinding.allowedOverrides`） |
| `executionMode` | enum | 否 | `POLICY_DRIVEN` 或 `MANUAL_ONLY`，默认 `MANUAL_ONLY` |

首功能不生成以下策略能力：

- 调度 cron / 事件触发
- 启停时间窗口
- 执行配额
- 下发对象集合

这些由 Java 后端在策略保存阶段补齐；AI 不猜。

## 5. `ReportDefinitionDraft`

### 5.1 定位

`ReportDefinitionDraft` **就是** `report-definition-v1.md` 定义的 `ReportDefinition`，仅在首功能阶段使用其**最小必要子集**。所有字段名、嵌套结构、枚举值与 `report-definition.schema.json` 一致，AI 不发明新字段。

### 5.2 首功能必须返回的顶层字段

| 字段 | 类型 | 来源章节 | 本阶段规则 |
| --- | --- | --- | --- |
| `schemaVersion` | string | §1.2 | 固定 `1.0` |
| `metadata` | `ReportMetadata` | 第 2 节 | `id`/`revision`/`status` 由服务端维护；AI 填 `name`、`description`、`tags` |
| `parameters` | Map | 第 2 节 | 首功能可为空对象 `{}` |
| `policyBinding` | `PolicyBinding` | 第 2 节 | 必填；`policyRef` 可为新建策略占位 `policy_pending` |
| `defaults` | `ReportDefaults` | 第 2 节 / 附录 | 必填；见 §5.3 |
| `page` | `PageSpec` | 第 5.1 节 / 附录 | 必填；本阶段用 `arrangement=GRID, columns=12` |
| `theme` | `ThemeSpec` | 附录 | 必填；`themeRef`/`version` 用平台默认值 |
| `datasets` | Map | 第 8 节 | 必填；每个数据集必须 `sourceRef` 来自目录 mock，不得编造 |
| `pipelines` | Map | 第 8 节 | 必填；首功能至少包含 `total_energy`、`device_ranking`、`hourly_trend` 三个计算 |
| `regions` | List<`ReportRegion`> | 第 3 节 / 附录 | 必填；见 §5.4 |
| `outputs` | Map<string, `OutputProfile`> | 附录 | 首功能至少包含 `html` |
| `intentBindings` | List<`IntentBinding`> | 第 11 节 | 必填；每条用户诉求都应有对应 IntentBinding |
| `dependencies` | `DependencyManifest` | 附录 | 由 Java 后端在发布时固定；AI 阶段可只填 `dataCatalogVersion` 等已知项 |

> 不在首功能返回：`extensions`（除非确有命名空间化扩展）。

### 5.3 `ReportDefaults` 首功能约束

| 字段 | 本阶段取值规则 |
| --- | --- |
| `locale` | `zh-CN` |
| `scope.subjectRef` | 等于 `AgentRequest.context.subjectRef` |
| `scope.selectors` | 空 Map，由具体区域 narrow |
| `timeWindow` | 使用 `CalendarWindow`，`unit=DAY`、`offset=-1`、`count=1`（昨日） |
| `grain.unit` | `HOUR`（小时趋势需求）或 `DAY`，由意图决定 |
| `preFilters` | 可为空数组 |
| `quality` | 使用 `report-definition-v1.md` 默认值；本阶段不覆盖 |
| `computation` | 同上 |

编辑态的具体钟点窗口使用本地扩展 `FIXED_INTERVAL`。它写入
`regions[i].context.timeWindow`，形状与编辑操作 `timeWindow` 一致：

```json
{
  "mode": "REPLACE",
  "value": {
    "type": "FIXED_INTERVAL",
    "timezone": "Asia/Shanghai",
    "start": "2026-10-21T14:00:00+08:00",
    "end": "2026-10-21T18:00:00+08:00"
  }
}
```

`start`、`end` 必须是带时区的 ISO 8601 时间，偏移须与 `timezone` 一致，且
`start < end`；校验失败不得应用编辑。原有全天 `CALENDAR` 口径不变。
本地 Python 保存/校验链路接受该扩展；Java 服务的同名类型与落库兼容性仍需协议方确认，
不能据此宣称生产保存/真实编译已支持。

### 5.4 `regions` 首功能最小集合

首功能机房能耗日报必须包含以下区域（顺序即渲染顺序）：

| 区域 ID | `role` | `component.type` | 说明 |
| --- | --- | --- | --- |
| `region_report_title` | `REPORT_TITLE` | `TEXT` | 报告标题 |
| `region_total_energy` | `SUMMARY` | `METRIC_CARD` | 昨日总耗电 |
| `region_device_ranking` | `DETAIL` | `TABLE` | 设备耗电排名表，`binding.topN=10` |
| `region_hourly_trend` | `TREND` | `CHART`，`chartKind=LINE` | 小时趋势 |
| `region_data_quality` | `QUALITY` | `DATA_QUALITY` | 覆盖率、缺失、新鲜度 |
| `region_analysis` | `ANALYSIS` | `ANALYSIS` | 基于已计算事实的解读 |

组件字段均按 `report-definition-v1.md` 附录（`MetricCardComponent`、`TableComponent`、`ChartComponent`、`DataQualityComponent`、`AnalysisComponent`、`TextComponent`）填写；本协议不复述。

### 5.5 禁止事项（AI 生成时）

- 不得编造 `datasets[*].sourceRef`、`pipelines[*].nodes[*].metricRef`、`themeRef`、`promptTemplateRef`，必须来自目录 / 指标 / 主题 / 提示词注册表（mock 阶段来自 `CatalogTool`、`MetricTool`）。
- `FormatSpec.unitLabel` 必须与真实单位一致，不得把 `Wh` 改名为 `kWh`，单位换算走 `UNIT_CONVERT` 节点（`report-definition-v1.md` §5.2 / §8）。
- `TEXT` / `ANALYSIS` 的 `template` 不得携带脚本或自由 HTML。
- `scope.mode` 只能 `INHERIT` / `NARROW`；不得通过模板扩张权限。

## 6. `ChangeSet`

对应 `report-definition-v1.md` 第 11 节「IntentBinding」/ 「ChangeSet」。首功能的 `ChangeSet` 用于「修改已有草稿」。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `baseDefinitionRevision` | integer | 是 | 基准版本号，用于并发编辑校验 |
| `changed` | List<`ChangeSetEntry`> | 是 | 本次修改的条目 |
| `unchanged` | List<`ChangeSetUnchanged`> | 否 | 显式声明未改动的区域（用于澄清） |
| `impact` | List<string> | 是 | 影响说明；例如「需要重取趋势图数据」 |
| `intentBindings` | List<`IntentBinding`> | 否 | 本次新增/更新的意图绑定，字段同 §5.2 的 `intentBindings` |

### `ChangeSetEntry`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `regionId` | string | 是 | 稳定区域 ID；禁止用数组下标 |
| `path` | string | 是 | JSON Pointer，相对于整个 `ReportDefinition` 根；例如 `/regions/region_hourly_trend/context/timeWindow` |
| `before` | JsonValue / null | 否 | 修改前值（可省略，由服务端比对） |
| `after` | JsonValue | 是 | 修改后值 |
| `summary` | string | 是 | 一句话业务摘要 |

### `ChangeSetUnchanged`

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `regionId` | string | 是 | 稳定区域 ID |
| `summary` | string | 是 | 为什么没改 |

规则：

- 修改趋势图时，必须显式说明「总耗电卡片不受影响」，对齐 `report-definition-v1.md` 第 11 节表格「图改为近七个完整自然日」。
- `path` 必须是 `IntentBinding.targetPaths` 中出现过的，或在本次 `intentBindings` 中新增。
- 用户确认后，由 Java 后端 `PATCH /smart-report/definitions/{id}` 原子应用。

## 9. 协议错误结构

### 9.1 `AgentError`

当请求本身格式错误、状态非法转移、未知字段等协议问题时使用；业务拦截用 `blocks`，业务追问用 `questions`。

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | enum | 是 | 见下 |
| `message` | string | 是 | 可展示说明 |
| `details` | Map<string, JsonValue> | 否 | 调试上下文 |

`code` 允许值：

| 值 | 含义 |
| --- | --- |
| `INVALID_REQUEST` | 请求字段缺失或类型错误 |
| `INVALID_STATE_TRANSITION` | `state` 不在允许转移集合内 |
| `UNKNOWN_SESSION` | `designSessionId` 不存在或过期 |
| `REVISION_CONFLICT` | `baseDefinitionRevision` 与服务端版本不一致 |
| `UPSTREAM_TIMEOUT` | 调 Java / 目录 / 指标工具超时 |
| `INTERNAL_ERROR` | 未分类内部错误 |

### 9.2 HTTP 状态码

| 场景 | HTTP | 说明 |
| --- | --- | --- |
| 正常对话 | 200 | 即使 `blocks`/`questions` 非空也返回 200；它们是业务结果 |
| 请求字段非法 | 400 | 配合 `error.code=INVALID_REQUEST` |
| 版本冲突 | 409 | 配合 `error.code=REVISION_CONFLICT` |
| 服务端错误 | 500 | 配合 `error.code=INTERNAL_ERROR` |

## 11. 协议与 Java 后端能力的分工

本章只提醒分工，不重复 `00_统筹.md` §5.3 的接口清单：

| 边界 | AI 后端做 | Java 后端做 |
| --- | --- | --- |
| 身份 / IAM | 透传上下文 | 校验与授权 |
| 数据目录 / 指标 | 查询摘要（经 `CatalogTool` / `MetricTool`） | 维护真实能力与版本 |
| 草稿保存 | 发出 `SAVE_DEFINITION_DRAFT` / `APPLY_CHANGE_SET` 请求 | 生成 `revision`、保存版本 |
| 校验 | 发出 `VALIDATE_DEFINITION` 请求 | 四层校验（结构 / 业务 / 契约 / 权限） |
| 预览 | 发出 `CREATE_PREVIEW_RUN` 请求、解释结果 | 实际取数 / 计算 / 质量检查 |
| 发布 / 正式执行 | 不涉及 | `ReportRelease` / `ReportRun` 正式流程 |

## 12. 会话与项目管理接口（v1.1 新增）

> 与 §3 的对话入口是两套接口：`/api/agent/chat` 负责「说话」，本节负责「存、列、找、改、删」。
> 数据落 SQLite（默认 `backend/data/haewu.db`，可用 `AI_SESSION_DB_PATH` 覆盖）。
> 完整设计见 `07_会话管理系统方案.md`。

### 12.1 会话接口

#### `POST /api/sessions`

新建会话，**只铸 id，不建库行**。库行在第一轮对话成功后随消息一起创建，避免侧边栏堆积「点开是空的」条目。

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string / null | 否 | 初始标题；缺省为「新对话」，首条真实用户消息到达后会被自动改成其前 20 字 |
| `workspaceId` | string / null | 否 | 归属项目 id |

响应 `SessionSummary`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 后端生成的会话 id，`sess_` 前缀 |
| `title` | string | 会话标题 |
| `state` | string | 初始为 `ANALYZING` |
| `workspaceId` | string / null | 归属项目 id |
| `messageCount` | integer | 消息条数，新建时为 0 |
| `createdAt` | string | ISO 8601；新建但尚未落库时为空串 |
| `updatedAt` | string | ISO 8601；同上 |

#### `GET /api/sessions`

会话列表，按 `updatedAt` 倒序（同时间按 id 倒序）。只返回**未删除且至少有一条消息**的会话。

Query 参数：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `workspaceId` | string | 否 | 按项目过滤 |
| `q` | string | 否 | 标题关键词模糊匹配 |
| `limit` | integer | 否 | 每页条数，默认 50，范围 1～200 |
| `offset` | integer | 否 | 偏移量，默认 0 |

响应 `SessionListResponse`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `items` | List<`SessionSummary`> | 会话摘要列表 |
| `total` | integer | 满足过滤条件的总会话数（不受分页影响） |

#### `GET /api/sessions/{sessionId}`

会话详情，供前端恢复现场。不存在返回 **404**。

响应 `SessionDetail`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `sessionId` | string | 会话 id |
| `title` | string | 会话标题 |
| `state` | string | 会话停在哪个状态机状态；恢复后作为下一次请求的入参 |
| `workspaceId` | string / null | 归属项目 id |
| `designSessionId` | string / null | 关联的设计会话 id |
| `reportDefinitionId` | string / null | 关联的报表定义 id |
| `previewRunId` | string / null | 关联的预览运行 id |
| `messageCount` | integer | 消息条数 |
| `snapshot` | object / null | 恢复所需的快照，键见 §12.3 |
| `pendingChoice` | object / null | 当前选择锁；`null` 表示没有待选项。结构见 §12.4 |
| `messages` | List<`SessionMessage`> | 全部消息，按 `seq` 升序 |
| `createdAt` | string | ISO 8601 |
| `updatedAt` | string | ISO 8601 |

`SessionMessage`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `seq` | integer | 会话内序号，从 1 递增 |
| `role` | string | `user` / `assistant` |
| `content` | string | 纯文本内容；assistant 消息等于其 `reply` |
| `payload` | object / null | assistant 消息的**完整响应体**（即 `AgentResponse` 结构），用于还原结构化卡片；user 消息为 `null` |
| `createdAt` | string | ISO 8601 |

> 恢复时**不能只回放文字**：`payload` 里的 `state` / `questions` / `blocks` / `domainObjects` 要一并还原，否则前后端状态不一致。Debug Trace 不入库，因此不恢复。

#### `PATCH /api/sessions/{sessionId}`

改标题或换项目。不存在返回 **404**。

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string / null | 否 | 新标题 |
| `workspaceId` | string / null | 否 | 新归属项目 id |

响应：`SessionSummary`。

#### `DELETE /api/sessions/{sessionId}`

**软删**：写 `deleted_at`，会话行保留，列表接口不再返回。不存在返回 **404**。成功返回 **204**（无响应体）。

> 软删行随后若再收到同 `sessionId` 的请求（前端还持有旧 id），后端会**物理清掉旧行并重建**，等价于一条新会话；不会沿用旧会话的消息与快照。

### 12.2 项目接口

> 代码里概念叫 `workspace`，界面文案叫「历史项目」，**不与业务上下文里的 `context.projectId` 混用**。

#### `GET /api/workspaces`

返回全部项目的列表，数组元素为 `WorkspaceItem`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 项目 id |
| `name` | string | 项目名 |
| `description` | string | 描述 |
| `subjectRef` | string / null | 业务对象类型，首功能为 `machine_room` |
| `subjectId` | string / null | 业务对象 id |
| `sessionCount` | integer | 该项目下的会话数 |
| `createdAt` | string | ISO 8601 |
| `updatedAt` | string | ISO 8601 |

#### `POST /api/workspaces`

请求体：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `name` | string | 是 | 项目名；**空白返回 400** |
| `description` | string | 否 | 描述，默认空串 |
| `subjectRef` | string / null | 否 | 业务对象类型 |
| `subjectId` | string / null | 否 | 业务对象 id |

响应：`WorkspaceItem`。

#### `PATCH /api/workspaces/{workspaceId}`

请求体：`name` / `description`（均可选）。不存在返回 **404**。响应：`WorkspaceItem`。

#### `DELETE /api/workspaces/{workspaceId}`

删除项目，**其下会话保留**，只是把 `workspaceId` 置为 `null`。不存在返回 **404**。成功返回 **204**。

### 12.3 `snapshot` 字段口径

`snapshot` 只存恢复右侧报表预览与继续对话所需的最小集合：

| 键 | 说明 |
| --- | --- |
| `definition` | `ReportDefinitionDraft`；恢复右侧预览用 |
| `policy` | `ReportPolicyDraft` |
| `lastReportRun` | `ReportRunPreview`；恢复预览结果用 |
| `previewPayload` | 预览运行的结果体；恢复时直接渲染，不再重跑 |
| `editingTargetRegionId` | 用户正在局部编辑的区域 id |

**恢复优先级**：`previewPayload` 存在 → 直接渲染最终报表；否则有 `definition` → 渲染草稿预览；否则显示空态。

### 12.4 `pendingChoice` 字段口径

选择锁存在库里（`sessions.pending_choice`），不是进程内存，因此后端重启后恢复历史会话仍能拿到锁，不会出现「前端放行自由输入、后端拒收」的前后端不一致。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `state` | string | 持锁时的状态机状态，如 `WAITING_USER_CONFIRM` / `READY` |
| `question` | `AgentQuestion` | 待选问题；`options` 非空且 `selectionOnly=true` 才会持锁 |

用户选定并提交后，锁被**清空**（写 `null`）。

> 恢复时的坑：历史消息回放出来的 `question` 是**新对象**，与当前 `pendingChoice.question` 不是同一引用。因此判定要按 `question.id` 比对，不能用对象引用相等。
