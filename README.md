# 智能报表 AI 原型版本说明

本目录记录智能报表 AI 功能从 v1 到 v3 的原型和功能清单演进。

---

## 1. 目录结构

| 目录 | 内容 | 定位 |
| --- | --- | --- |
| `v1/` | 第一版墨刀 Prompt 和原型页面 | 拖拽式报表设计器 + AI 辅助面板。 |
| `v2/` | AI 优先轻量版功能清单、Prompt 和原型页面 | 去掉复杂拖拽设计器，突出 AI 对话生成、修改、校验、保存。 |
| `v3/` | 不对用户暴露数据治理入口的功能清单和原型页面 | 用户报表生成页只保留报表相关能力，数据治理放到后台 / Skill 平台。 |
| `backend/` | AI 后端统筹和第一版 FastAPI 骨架 | 先用机房耗电量报表跑通后端链路。 |
| `工具栈选择与讨论.md` | 技术栈讨论 | 只讨论选型，不承载 PRD。 |

---

## 2. v1：拖拽设计器 + AI 面板

v1 的核心思路是：在传统报表设计器里加入 AI 助手。

主要特点：

- 页面结构偏完整报表设计器。
- 用户可以拖拽组件、选择数据、配置属性。
- AI 作为右侧辅助面板，帮助生成草稿、修改组件、解释校验错误。
- 人工拖拽和 AI 修改共同作用在同一份报表草稿上。

这一版适合表达“AI 加到已有报表设计器里”，但页面偏重，容易回到传统 BI / 拖拽设计器思路。

---

## 3. v2：AI 优先轻量版

v2 的核心变化是：不再强调完整拖拽式设计器，而是先验证 AI 生成报表的轻量闭环。

主要特点：

- 页面重点变成 AI 对话输入、报表预览、自然语言修改、变更确认、校验结果、保存草稿。
- 不做左侧组件拖拽区、自由拖拽画布、底部复杂属性面板。
- 用户主要通过自然语言生成和修改报表。
- 人工操作只保留接受 / 拒绝变更、删除模块、切换图表类型、保存草稿等轻量动作。

这一版的重点是先跑通：

```text
用户自然语言需求
  -> AI 生成结构化报表草稿
  -> 前端预览
  -> 用户继续自然语言修改
  -> 用户确认变更
  -> 后端校验
  -> 保存草稿
```

---

## 4. v3：用户页不暴露数据治理入口

v3 是在 v2 的基础上继续收敛信息架构。

主要变化：

- 普通用户的报表生成页面不再暴露 `数据源管理`、`数据集`、`指标口径`、`权限管理` 等后台治理入口。
- 用户页面只保留报表生成、预览、修改、校验、保存等能力。
- 数据源、数据集、指标口径、权限等能力仍然存在，但应该放在后台管理、Skill 平台或数据工程师配置侧。
- AI 使用数据能力时，后续应通过 Skill / MCP / 后端接口发现和调用，不应在报表生成页 hard code 固定数据集。
- 用户流程增加“先确认报表框架，再补日期、location、范围等条件”的思路。

v3 更接近泛 AI Agent 中台视角：首功能只是机房耗电量报表，但底层能力要尽量可复用。

---

## 5. 三版关系

| 版本 | 核心问题 | 结果 |
| --- | --- | --- |
| v1 | AI 怎么嵌进传统报表设计器 | 有完整设计器感，但过重。 |
| v2 | 能不能用 AI-first 的轻量方式生成报表 | 去掉重拖拽，突出 AI 生成闭环。 |
| v3 | 用户页是否应该暴露数据治理入口 | 不暴露，治理能力放后台 / Skill 平台。 |

当前建议以 v3 作为前端原型方向，v2 作为上一版对照，v1 作为早期探索记录。
