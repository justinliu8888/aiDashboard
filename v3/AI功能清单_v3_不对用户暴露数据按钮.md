# 智能报表 AI 功能 PRD（v3：用户页不暴露数据治理入口）

本文说明智能报表 v3 阶段的 AI 功能范围：面向谁、实现什么功能、用户页面展示什么、数据治理能力放在哪里，以及哪些事情 AI 不能做。

v3 的核心变化：用户生成报表页面不暴露 `数据源管理`、`数据集`、`指标口径`、`权限管理` 等后台治理入口；这些能力保留在 Skill 平台 / 后台管理 / 数据工程师配置侧，AI 通过受控 Skill / MCP / 后端接口使用。

---

## 1. v3 定位

智能报表 AI 是一个“AI-first 报表生成助理”。

用户主要通过自然语言描述想要的报表，AI 帮忙生成报表初稿、局部修改模块、解释校验错误，并在口径不清、数据不支持、权限越界或危险动作时主动拦截或追问。

v3 阶段验证的是“AI 生成 + 框架确认 + AI 修改 + 人工确认”的闭环：

```text
用户进入 AI 报表生成工作台
  -> 用户输入自然语言报表需求
  -> AI 先生成报表框架 / 模板
  -> 用户确认框架是否符合意图
  -> 用户再补日期、location、范围等条件
  -> AI 生成结构化报表草稿
  -> 前端渲染报表预览
  -> 用户继续用自然语言修改
  -> AI 展示变更确认
  -> 用户接受或拒绝
  -> 后端校验
  -> AI 辅助修正问题
  -> 用户预览并保存草稿
```

v3 不做复杂拖拽画布、左侧组件拖拽区和底部复杂属性面板。人工操作只保留轻量能力：确认报表框架、补充参数、接受/拒绝变更、删除模块、切换图表类型、保存草稿。

v3 信息架构原则：普通用户页面只暴露报表生成、预览、修改、校验、保存；数据源、数据集、指标口径、权限等治理能力不放在用户生成报表页面。

## 2. 目标用户

| 用户 | 关心什么 | AI 帮什么 |
| --- | --- | --- |
| 报表管理员 | 快速创建可校验、可预览的报表草稿 | 生成初稿、修改模块、处理校验错误。 |
| 运营 / 能效人员 | 用业务语言表达分析诉求 | 把“昨日能耗日报”“近 7 天趋势”“异常设备排名”转成报表内容。 |
| 平台管理员 / 数据工程师 | 数据和指标不能乱用 | 在 Skill 平台 / 后台侧维护数据能力、指标口径、权限和 MCP 配置。 |
| 管理层 / 使用者 | 看懂结果和原因 | AI 基于已计算结果生成分析说明，不能编造数据。 |

## 3. 功能范围

### 3.1 必须实现

| 功能 | 说明 |
| --- | --- |
| 自然语言生成报表初稿 | 用户描述报表目标，AI 生成标题、指标卡、图表、表格和基础布局，形成可预览草稿。 |
| 报表框架确认 | AI 先生成报表框架，让用户确认“是不是想要这个结构”，确认后再补条件和取数。 |
| 自然语言修改报表 | 用户继续输入“把趋势改成近 7 天”“加异常设备 Top10 表”，AI 生成修改建议。 |
| AI 修改定位 | AI 修改必须绑定目标模块 ID；跨模块修改必须明确说明影响范围。 |
| 变更确认 | AI 修改前展示“准备改哪里、影响什么”，用户可接受或拒绝。 |
| 意图拦截与追问 | 口径不清、数据不存在、权限越界、能力不支持或危险动作时，AI 不直接生成，而是提示、追问或拒绝。 |
| 校验错误辅助修正 | 校验失败后，用户可以把错误发给 AI，让 AI 给出原因、替代字段或修改方案。 |
| AI 修正次数限制 | 校验失败后 AI 可以给出修正建议，但不允许无限自动修正；每次修正都需要用户确认后再应用。 |
| 轻量人工操作 | 用户可以接受/拒绝修改、删除模块、切换图表类型、确认口径、保存草稿。 |
| AI 使用依据展示 | 展示 AI 使用的数据源、指标、权限范围、假设和待确认问题。 |
| AI 分析说明 | 在结果查看阶段，基于已计算结果生成文字分析和数据质量提示。 |
| 用户页隐藏治理入口 | 用户生成报表页面不展示数据源管理、数据集、指标口径、权限管理等后台菜单。 |

### 3.2 暂不实现

| 不做 | 说明 |
| --- | --- |
| 完整拖拽式报表设计器 | v3 不做左侧组件拖拽、中间自由画布、底部属性面板。 |
| 复杂字段绑定配置 | 不让用户手工配置大量字段，优先通过 AI 对话生成和修改。 |
| AI 直接执行 SQL 或脚本 | 危险动作直接拒绝。 |
| AI 直接生成 React / Vue 前端代码 | AI 只生成结构化报表草稿或修改建议。 |
| AI 绕过校验直接发布结果 | 保存、校验、试运行、发布必须由后端控制。 |
| AI 自己创建数据源或指标口径 | 数据源和指标必须由平台登记和治理。 |
| 完整智能 BI 能力 | v3 只做“生成 + 框架确认 + 预览 + 修改 + 校验 + 保存”的闭环。 |
| 在用户页暴露数据治理菜单 | `数据源管理`、`数据集`、`指标口径`、`权限管理` 不放在普通报表生成页面。 |

### 3.3 数据能力范围

第一版先接入机房耗电量相关数据能力，验证 AI 生成、框架确认、校验和预览闭环。数据能力不在用户页面手动配置，而是由 Skill 平台 / 后台能力提供。

| 数据 | 定位 | v3 用途 |
| --- | --- | --- |
| 设备能耗历史数据集 | 核心业务数据集 | 生成总耗电、能耗趋势、设备能耗排名、单位运行耗电等内容。 |
| 设备告警历史数据集 | 核心业务数据集 | 生成告警数量、告警等级分布、异常设备列表、告警趋势等内容。 |
| 设备目录 | 基础维表 / 权限范围 | 补充设备名称、项目、机房、设备类型和权限范围，不作为独立业务分析数据集计算。 |

v3 阶段，AI 只能基于已登记、可发现、当前用户有权限的数据能力生成报表草稿或修改建议；不能自行创建数据源、伪造字段或绕过设备目录权限范围。

后续泛 AI Agent 中台方向下，数据能力应支持通过 Skill / MCP 发现，不应在报表生成功能里 hard code 固定数据集。当前这是设计方向假设，后续还需要结合平台 Skill 能力继续确认。

## 4. 页面范围

### 4.1 AI 报表生成工作台

核心页面，用户在这里通过自然语言生成和修改报表，前端展示报表预览、AI 依据、变更确认和校验入口。

| 区域 | 内容 |
| --- | --- |
| 顶部操作栏 | 报表名称、策略版本、定义草稿版本、重新生成、校验、试运行、保存草稿、发布。 |
| AI 对话区 | 用户输入需求、AI 生成初稿、自然语言修改、意图追问、使用依据、变更确认、修正建议。 |
| 报表预览区 | 展示 AI 生成的指标卡、趋势图、排名表、告警分布、异常设备列表。 |
| 轻量模块操作 | 让 AI 修改、删除模块、切换图表类型、查看数据依据。 |

顶部导航只保留报表相关入口，例如 `报表中心`、`报表策略`。不在普通用户页面展示 `数据源管理`、`数据集`、`指标口径`、`权限管理`。

### 4.2 AI 变更确认卡片

用于在 AI 对话窗口中展示 AI 局部修改前后的变化。

示例：用户输入“把趋势图改成近 7 天趋势”。

| 信息 | 示例 |
| --- | --- |
| 目标模块 | 小时能耗趋势 `energy_trend` |
| 原配置 | 统计窗口 = 昨日，粒度 = 小时 |
| 新配置 | 统计窗口 = 近 7 天，粒度 = 小时 |
| 影响范围 | 只影响趋势图，不影响总耗电卡片、设备排名和告警分布。 |
| 用户操作 | 接受变更、拒绝、查看结构化变更、继续追问。 |

### 4.3 校验与试运行面板

用于在用户保存或发布前，检查当前报表草稿是否可执行，并生成预览结果。它不是正式结果页，而是“预览前的检查 + 试跑”入口。

| 模块 | 内容 |
| --- | --- |
| 校验状态 | 结构校验、字段校验、指标口径校验、权限校验、试运行状态。 |
| 执行计划 | 展示本次预览要执行的节点，如设备目录、能耗历史、告警历史、小时趋势、设备排名、渲染报表。 |
| 预览参数 | 展示时间范围、对象范围、设备数量、完整试运行或抽样预览模式。 |
| 校验结果 | 展示错误、警告和提示，例如字段不存在、指标未登记、异常阈值未确认。 |
| AI 修正入口 | 用户可点击“发送问题给智能体”，让 AI 在对话窗口中给出修正建议；复杂问题可打开详情面板。 |
| 预览入口 | 校验和试运行通过后，用户点击“查看预览结果”。 |

### 4.4 校验失败后 AI 修正建议卡片

用于在 AI 对话窗口中展示校验失败原因和修正方案；复杂错误可打开详情面板。

示例：字段 `outdoor_temperature` 不存在。

| 信息 | 示例 |
| --- | --- |
| 错误类型 | 字段不存在 |
| 错误位置 | 小时能耗趋势 / 数据绑定 |
| 错误字段 | `outdoor_temperature` |
| AI 分析 | 当前设备能耗历史数据集中没有该字段。 |
| 修正方案 | 替换为 `room_temp`、移除相关分析、切换到支持室外温度的数据源。 |
| 用户操作 | 应用方案、查看影响、拒绝建议、继续提问。 |

### 4.5 报表结果页 AI 分析说明区

用于在报表结果查看阶段解释运行结果。

| 模块 | 内容 |
| --- | --- |
| 结果摘要 | 总耗电、环比、异常设备、告警数量、数据完整度。 |
| AI 分析说明 | 基于已计算结果说明趋势变化、异常原因、数据质量影响。 |
| 引用依据 | 指标、设备排名、告警历史、异常设备、数据质量报告。 |
| 数据质量提示 | 缺失采样、数据延迟、分页完整性等。 |
| 边界提示 | AI 分析只解释已归档结果，不改写正式数据和报表口径。 |

## 5. 用户操作流程

### 5.1 页面跳转关系

v3 只有一个主工作台，其他能力以面板、卡片或结果页承载。

```text
报表策略 / 新建策略
  -> AI 报表生成工作台
      -> 用户输入自然语言需求：AI 先生成报表框架
      -> 用户确认框架：再补充日期、location、范围等条件
      -> AI 根据确认后的框架和条件生成报表预览
      -> 用户继续输入修改要求：AI 对话区展示变更确认卡片
      -> 点击“校验 / 试运行”：打开校验与试运行面板
      -> 校验失败后点击“发送问题给智能体”：AI 对话区展示修正建议卡片
      -> 校验和试运行通过后点击“查看预览结果”：进入报表结果页或预览页
```

| 页面 / 面板 | 进入方式 | 离开方式 |
| --- | --- | --- |
| AI 报表生成工作台 | 用户创建或编辑报表策略后进入 | 保存草稿、发布、返回策略列表，或进入校验与试运行。 |
| AI 变更确认卡片 | 用户在 AI 对话区提出修改后出现 | 接受后更新预览；拒绝后保持原草稿；继续追问仍留在 AI 对话区。 |
| 校验与试运行面板 | 在工作台点击“校验”或“试运行”打开 | 关闭返回工作台；通过后点击“查看预览结果”。 |
| AI 修正建议卡片 | 校验失败后点击“发送问题给智能体”出现 | 应用方案后回到工作台并重新校验；拒绝后保持原草稿。 |
| 报表结果页 AI 分析说明区 | 试运行预览或正式结果查看时展示 | 返回工作台继续调整，或返回结果列表。 |

### 5.2 首次生成报表

| 步骤 | 用户动作 | 系统 / AI 反应 |
| --- | --- | --- |
| 1 | 用户创建报表策略，进入 AI 报表生成工作台 | 系统打开 AI 对话区和空白预览区。 |
| 2 | 用户输入“我想生成机房耗电量报表” | AI 先生成报表框架，例如总耗电、趋势、设备排名、异常设备。 |
| 3 | 用户确认框架 | AI 再引导用户补充日期、location、范围等条件。 |
| 4 | 条件足够 | AI 根据已确认框架和条件生成结构化报表草稿，右侧预览区渲染报表。 |
| 5 | 信息不足或口径不清 | AI 在对话窗口追问，例如“异常设备按什么口径判断？”。 |
| 6 | 用户确认当前草稿 | 用户点击保存草稿，或点击校验 / 试运行进入检查流程。 |

### 5.3 自然语言修改报表

| 操作方式 | 示例 | 页面表现 |
| --- | --- | --- |
| AI 首次生成 | 用户说“生成昨日机房能耗日报” | AI 生成一组模块和布局，预览区渲染草稿。 |
| AI 修改 | 用户说“把趋势图改成近 7 天趋势” | AI 对话区展示变更确认卡片，用户接受后更新预览。 |
| AI 补充 | 用户说“再加一个异常设备 Top10 表” | AI 展示新增模块建议，用户接受后预览区新增模块。 |
| 轻量人工操作 | 用户删除模块或切换图表类型 | 预览区更新模块，复杂配置仍引导用 AI 对话完成。 |
| 用户确认 | 用户点击接受、拒绝或继续追问 | 接受则更新草稿；拒绝则保持原草稿；继续追问仍在 AI 对话区完成。 |

### 5.4 校验与试运行

| 步骤 | 用户动作 | 系统 / AI 反应 |
| --- | --- | --- |
| 1 | 用户在工作台点击“校验”或“试运行” | 系统打开校验与试运行面板。 |
| 2 | 系统检查当前报表草稿 | 展示结构校验、字段校验、指标口径校验、权限校验和试运行状态。 |
| 3 | 系统按当前参数试跑 | 展示执行计划、预览参数、数据量、耗时和质量问题。 |
| 4 | 校验通过 | 用户可点击“查看预览结果”，进入报表结果页或预览页。 |
| 5 | 校验失败 | 面板展示错误和警告，用户可点击“发送问题给智能体”。 |

### 5.5 校验失败后的 AI 修正

| 场景 | AI 处理方式 | 页面表现 |
| --- | --- | --- |
| 字段不存在 | 提示当前数据源没有该字段，并建议可替代字段 | AI 对话区展示修正建议卡片。 |
| 指标口径未登记 | 提示需要先创建或选择已登记指标 | AI 给出可选处理方式，但不直接创建指标。 |
| 权限不足 | 告诉用户该范围不可用，建议缩小到有权限范围 | AI 给出缩小范围后的生成建议。 |
| 口径不清 | 追问统计方式、时间范围、异常阈值等 | AI 在对话中提供选项卡片，用户选择后继续生成。 |

### 5.6 AI 对话中的意图拦截

意图拦截不是独立页面，而是 AI 对话能力。用户在 AI 对话区输入需求后，AI 先判断需求是否完整、合法、可执行，再决定生成、追问、提示不支持或拒绝。

| 场景 | 用户输入 | AI 对话处理 |
| --- | --- | --- |
| 口径不清 | “帮我找异常设备” | AI 追问异常定义，并在对话中提供阈值、对比口径、时间范围等选项。 |
| 数据不支持 | “看去年每分钟能耗” | AI 提示当前只有小时级数据，建议改用小时粒度。 |
| 权限越界 | “看所有项目能耗” | AI 提示当前只有 A 机房权限，建议缩小到有权限范围。 |
| 危险动作 | “直接跑 SQL 删除旧数据” | AI 直接拒绝，并说明不能执行 SQL、删除数据或绕过权限。 |

### 5.7 结果查看阶段

| 步骤 | 用户动作 | 系统 / AI 反应 |
| --- | --- | --- |
| 1 | 用户在校验与试运行面板点击“查看预览结果” | 系统打开报表结果页或预览页，展示本次试运行结果。 |
| 2 | 用户查看指标卡、图表和表格 | 页面展示总耗电、趋势、排名、告警和异常设备。 |
| 3 | 用户查看 AI 分析说明 | AI 基于本次运行结果生成文字分析、异常说明和数据质量提示。 |
| 4 | 用户发现结果不满意 | 返回工作台继续用自然语言修改。 |
| 5 | 用户确认结果可用 | 保存草稿，后续进入发布流程。 |

## 6. AI 拦截规则

| 拦截类型 | 示例 | 处理方式 |
| --- | --- | --- |
| 口径不清 | “帮我找异常设备” | 追问异常定义，例如阈值、对比口径、时间范围。 |
| 数据不支持 | “看去年每分钟能耗”但系统只有小时数据 | 告知不支持，并建议使用小时粒度。 |
| 权限越界 | “看所有项目能耗”但用户只有 A 项目权限 | 拒绝越权范围，建议改成有权限范围。 |
| 危险动作 | “直接跑 SQL 删除旧数据” | 直接拒绝。 |
| 能力不支持 | “生成一个未登记算法的复杂模型预测” | 标记暂不支持，建议转人工或后续扩展。 |

## 7. 产品规则

| 规则 | 说明 |
| --- | --- |
| AI 是生成助理 | AI 生成初稿和修改建议，不直接决定能否发布。 |
| 后端是守门员 | 保存、校验、试运行、发布和执行都要后端控制。 |
| 用户有最终确认权 | AI 的修改必须能被查看、接受、拒绝和撤销。 |
| 用户主要用自然语言修改 | v3 不要求用户手工拖拽和配置大量属性。 |
| 先确认框架再补条件 | AI 先让用户确认报表结构，再引导补日期、location、范围等条件。 |
| 用户页不暴露数据治理 | 数据源、数据集、指标口径、权限管理不出现在普通报表生成页面。 |
| 数据能力走 Skill / MCP / 后端 | 报表生成页不 hard code 数据能力，后续由 Skill 平台或 MCP 发现可用能力。 |
| AI 修改必须有定位 | 针对模块的 AI 修改必须绑定模块 ID；跨模块修改必须先说明影响范围。 |
| AI 修正不能无限自动执行 | 校验失败后的 AI 修正需要用户逐次确认，不能连续自动修改到通过为止。 |
| 结果不能被 AI 编造 | 分析文字只能基于已计算事实和数据质量信息。 |
